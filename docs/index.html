Native macOS Wi-Fi for Intel cards, from 802.11n to Wi-Fi 7

macOS Tahoe 26 and Sequoia 15 · WPA3 · 6 GHz · 802.11be · BE200 / BE201 and every card itlwm supports

AirportItlwm taken from Wi-Fi 6 to Wi-Fi 7 (BE200, BE201), with AirDrop and Instant Hotspot on the way. Every card it supported still works, on macOS's own Wi-Fi, with no HeliPort.

The firmware for every card is built into the kext. For the BE family the hardware revision picks the firmware and the highest adapted API is tried first. Not supported yet: the Wi-Fi 7 "SC" generation (BE211/BE213, 6E70 D240 D340 E340 E440 9327), which needs firmware this project does not ship.

Install

  1. Download the package for your macOS from Releases: macOS26-Tahoe for macOS 26, macOS15-Sequoia for macOS 15.2 or later. Release for daily use; Debug keeps the diagnostic logs a report needs.
  2. Put the kext in EFI/OC/Kexts/ and add it to Kernel → Add. Use only one Intel Wi-Fi kext. If one config boots both systems, limit the Tahoe kext to Darwin 25.0.0–25.99.99 and the Sequoia kext to 24.2.0–24.99.99.
  3. Do not combine it with OpenCore Legacy Patcher's "Modern Wireless" root patches or any IO80211 / Skywalk replacement: this driver uses the system's own Wi-Fi stack.
  4. Keep a bootable copy of your EFI and test from a USB stick first.

The country and the channels allowed in it come from the networks around you, through the card's own regulatory logic, as on Linux. There is nothing to set.

Continuity

🧪 In development

Instant Hotspot

The Bluetooth wake-up of the iPhone's hotspot, the directed scan and the WPA3 association work; the iPhone currently drops the link right after the four-way handshake. This is the open bug, and the fix applies to every card.

AirDrop (AWDL)

awdl0 is created and macOS's own AWDL stack drives it. AirDrop needs the card to listen on AWDL's channel while staying on your network. Every Intel card except the AX411 has a single radio (Wi-Fi 7 eMLSR is single radio too), so the firmware time-shares the two:

  • AX cards (pre-MLD firmware): a standing listener with its own channel context, the construction ForbiddenItlwm runs on the AX211 with AirDrop working both ways.
  • BE cards (MLD firmware): the same idea in the MLD command set, as a P2P client link next to the station link (the combination Linux allows on two channels). The firmware's activation rules are being worked out from its own code; not working yet.
  • AC and older: not planned.

Bluetooth LE advertising and scanning must work on macOS first. Test packages ship a matching BlueToolFixup with -btlfxadvsets (LE advertising sets for third-party controllers, macOS 26.4–26.7.3) and -btlfxrpa (connecting to an iPhone that uses a private address; macOS 26.4 and 26.7 so far). With -itlawdl the driver first checks that Apple's AWDL interface table has the layout it was built for (AWDLBuildCheck in the I/O Registry) and otherwise runs as plain Wi-Fi, so a macOS update cannot turn it into a kernel panic. The listening channel is 149, then 44, then 6, and only one the country allows transmitting on (44 where there is no 149; a passive channel once a nearby router is heard beaconing on it). 149 is fastest: routers on 149 and an iPhone on 149 or off Wi-Fi give the best AirDrop speed.

Reporting a problem

Use the Debug package. Reproduce the problem once, then run Collect-WiFi-Community.command from the package and attach the archive to a GitHub issue with your card, macOS build, router model, security mode and what you did. For a Wi-Fi 7 router say whether MLO is on and which bands it combines. The archive holds network metadata: send it privately if you prefer. A build that compiles is not a result; please say what you saw on your machine.
