開放原始碼 · GPL-2.0 · x86_64

Intel 無線網卡的 macOS 原生驅動程式，從 802.11n 到 Wi-Fi 7

macOS Tahoe 26、Sequoia 15 · WPA3 · 6 GHz · 802.11be · BE200 / BE201 以及 itlwm 支援的所有網卡

在 AirportItlwm 的 Wi-Fi 6 基礎上做到了 Wi-Fi 7（BE200、BE201），並持續開發 AirDrop（隔空投送）與即時熱點。原有網卡全部保留，使用 macOS 內建的 Wi-Fi，不需要 HeliPort。

安裝

  1. 在 Releases 下載對應系統的套件：macOS 26 使用 macOS26-Tahoe，macOS 15.2 以上使用 macOS15-Sequoia。日常使用 Release；Debug 保留回報問題所需的診斷日誌。
  2. 放進 EFI/OC/Kexts/，並在 Kernel → Add 中加入，只保留一個 Intel 無線驅動。同一份設定同時開機兩個系統時，Tahoe 版限定 Darwin 25.0.0–25.99.99，Sequoia 版限定 24.2.0–24.99.99。
  3. 不要與 OpenCore Legacy Patcher 的「Modern Wireless」根修補或任何 IO80211 / Skywalk 替換混用：本驅動使用的就是系統內建的無線堆疊。
  4. 保留一份可以開機的 EFI，先用隨身碟測試。

國家碼與可用頻道由周圍的路由器透過網卡自身的法規邏輯決定，與 Linux 相同，不需要設定。

即時熱點

藍牙喚醒 iPhone 熱點、定向掃描與 WPA3 關聯都已能完成；目前 iPhone 在四向交握之後立刻中斷連線，這是正在追查的問題，修正對所有網卡都有效。

AirDrop 隔空投送（AWDL）

awdl0 已經建立，由 macOS 自己的 AWDL 協定堆疊驅動。AirDrop 要求網卡一邊留在你的網路上，一邊在 AWDL 頻道上監聽。除 AX411 之外，所有 Intel 網卡都是單射頻（Wi-Fi 7 的 eMLSR 也是單射頻），由韌體在兩者之間分時：

  • AX 系列（非 MLD 韌體）：常駐監聽器，擁有自己的頻道上下文，與 ForbiddenItlwm 在 AX211 上實現雙向 AirDrop 的做法相同。
  • BE 系列（MLD 韌體）：同樣的思路改用 MLD 指令集，在主連結旁加一條 P2P 用戶端連結（Linux 允許兩個不同頻道的組合）。正在依韌體自身程式碼梳理它的啟用條件，尚未走通。
  • AC 及更早：不在規劃內。

前提是藍牙 LE 廣播與掃描在 macOS 上可用。測試套件附帶配套的 BlueToolFixup，支援 -btlfxadvsets（第三方控制器的 LE 廣播組，macOS 26.4–26.7.3）與 -btlfxrpa（連接使用私人位址的 iPhone，目前支援 macOS 26.4 與 26.7）。加入 -itlawdl 時，驅動會先檢查 Apple 的 AWDL 介面表是否與編譯時一致（I/O Registry 中的 AWDLBuildCheck），不一致就只做一般 Wi-Fi，系統更新不會因此造成核心當機。監聽頻道依序選 149、44、6，只使用當地允許發射的頻道（沒有 149 的國家使用 44；被動頻道在聽到附近路由器的信標後才算可用）。149 最快：路由器在 149、iPhone 也在 149 或未連接 Wi-Fi 時，AirDrop 速度最好。

回報問題

請使用 Debug 套件。先重現一次問題，再執行套件內的 Collect-WiFi-Community.command，把產生的壓縮檔附到 GitHub Issue，並寫明網卡、macOS 版本、路由器型號、加密方式與操作過程；Wi-Fi 7 路由器請說明是否開啟 MLO、組合了哪些頻段。壓縮檔包含網路中繼資料，可以私下傳送。能編譯不等於能用，請寫下你在自己機器上看到的結果。
