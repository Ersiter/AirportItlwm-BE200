Intel 无线网卡的 macOS 原生驱动，从 802.11n 到 Wi-Fi 7

macOS Tahoe 26、Sequoia 15 · WPA3 · 6 GHz · 802.11be · BE200 / BE201 以及 itlwm 支持的全部网卡

在 AirportItlwm 的 Wi-Fi 6 基础上做到了 Wi-Fi 7（BE200、BE201），并在做隔空投送、即时热点。原有网卡全部保留，用的是 macOS 自带的 Wi-Fi，不需要 HeliPort。

安装

  1. 在 Releases 下载对应系统的包：macOS 26 用 macOS26-Tahoe，macOS 15.2 及以上用 macOS15-Sequoia。日常用 Release；Debug 保留反馈问题所需的诊断日志。
  2. 放进 EFI/OC/Kexts/，在 Kernel → Add 里添加，只保留一个 Intel 无线驱动。一份配置同时引导两个系统时，Tahoe 版限定 Darwin 25.0.0–25.99.99，Sequoia 版限定 24.2.0–24.99.99。
  3. 不要与 OpenCore Legacy Patcher 的「Modern Wireless」根补丁或任何 IO80211 / Skywalk 替换混用：本驱动用的就是系统自带的无线栈。
  4. 保留一份能启动的 EFI，先用 U 盘测试。

国家码和可用信道由周围的路由器经网卡自身的法规逻辑确定，与 Linux 相同，不需要设置。

即时热点

蓝牙唤起 iPhone 热点、定向扫描、WPA3 关联都已能完成；目前 iPhone 在四次握手后立刻断开，这是正在查的问题，修复对所有网卡都有效。

隔空投送（AWDL）

awdl0 已经创建，由 macOS 自己的 AWDL 协议栈驱动。隔空投送要求网卡一边留在你的网络上，一边在 AWDL 信道上监听。除 AX411 外所有 Intel 网卡都是单射频（Wi-Fi 7 的 eMLSR 也是单射频），由固件在两者之间分时：

  • AX 系列（非 MLD 固件）：常驻监听器，有自己的信道上下文，与 ForbiddenItlwm 在 AX211 上实现双向隔空的做法相同。
  • BE 系列（MLD 固件）：同样的思路换成 MLD 命令集，在主链路旁加一条 P2P 客户端链路（Linux 允许两条不同信道的组合）。正在按固件自身代码梳理它的激活条件，尚未走通。
  • AC 及更早：不在计划内。

前提是蓝牙 LE 广播与扫描在 macOS 上可用。测试包附带配套的 BlueToolFixup，支持 -btlfxadvsets（第三方控制器的 LE 广播集，macOS 26.4–26.7.3）和 -btlfxrpa（连接使用私有地址的 iPhone，目前支持 macOS 26.4 与 26.7）。加了 -itlawdl 时，驱动先检查 Apple 的 AWDL 接口表是否与编译时一致（I/O Registry 里的 AWDLBuildCheck），不一致就只做普通 Wi-Fi，系统更新不会因此变成内核崩溃。监听信道依次选 149、44、6，只用当地允许发射的信道（没有 149 的国家用 44；被动信道在听到附近路由器的信标后才算可用）。149 最快：路由器在 149、iPhone 也在 149 或没连 Wi-Fi 时隔空速度最好。

反馈问题

请用 Debug 包。先复现一次问题，再运行包里的 Collect-WiFi-Community.command，把生成的压缩包附到 GitHub Issue，写明网卡、macOS 版本、路由器型号、加密方式和操作过程；Wi-Fi 7 路由器请说明是否开了 MLO、组合了哪些频段。压缩包含网络元数据，可以私下发送。能编译不等于能用，请写你在自己机器上看到的结果。
