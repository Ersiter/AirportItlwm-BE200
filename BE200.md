Target: Intel BE200 PCI `8086:272B`, subsystem `8086:00F4`, on x86_64 macOS
Tahoe 26.4 / Darwin 25.4.0. The first hardware milestone is ordinary WPA2
infrastructure networking. Wi-Fi 7, MLO and AirDrop are outside this milestone.
The experiment scans 2.4/5 GHz and negotiates HT/VHT. HE, EHT, 6 GHz, PMF,
monitor mode and non-CCMP keys are not supported by this initial path.

The [cc42012 build](https://github.com/Ersiter/AirportItlwm-BE200-Tahoe/actions/runs/38577935451)
passed on Xcode 16.4 / build 16F6. This confirms compilation of the new source
and its packed-size assertions. That build did not establish MSI-X delivery,
firmware ALIVE or PNVM matching. Scanning, WPA2 key completion, DHCP and packet
transfer remain unverified.
LINK/STA commands absent from the GL-86 version table use the reference v1
layout; hardware must confirm that assumption.

The first hardware capture matched the cc42012 executable UUID, but showed no
AirportItlwm controller below the PCI wrapper and no wireless interface. The
historical kernel-log query timed out. This does not establish which startup
operation failed, or whether firmware ALIVE was reached.

The diagnostic build writes `AirportItlwm-StartupStage` to the PCI wrapper and
`AirportItlwm-HALStage`, `AirportItlwm-HWRevisionRaw`, `AirportItlwm-RFID` and
`AirportItlwm-PreinitError` to the PCI device. These survive a failed controller
start. A stage identifies the last attempted operation, not its success;
`controller-ready` and `attach-ready` identify completed startup. Read both the
wrapper and its PCI parent with ioreg. This build changes diagnostics only.

The next capture loaded diagnostic UUID `7D749C71-9C1B-3144-A114-B04BDE330AE9`.
It reached firmware preinitialization and returned EINVAL (22). GL-86 has 70
runtime sections, including separators, while the inherited storage array held
60. The real driver storage function reproduces EINVAL on section 61. Its
capacity is now 70; the overflow check remains in place. The same test accepts
all 70 sections and checks their LMAC/UMAC/paging grouping against the context
DMA arrays, and also accepts the existing SO-68 image. This fixes a demonstrated
parser limit. Firmware stages and parse errors are now retained in IORegistry.

The subsequent hardware capture loaded UUID
`34B69DE7-A606-36F4-9B7D-D86E184526F9` and reached `load-pnvm` with EINVAL (22).
That stage follows successful firmware startup and ALIVE validation. The inherited
`strrchr` substitute returned one byte after the final separator, producing
`iwlwifi-gl-c0-fm-c0-.pnvm` instead of the embedded resource name
`iwlwifi-gl-c0-fm-c0.pnvm`. Its return semantics are now corrected. The regression
compiles the actual search function and PNVM name generation fragment, resolves
the GL and existing PNVM resources, and checks absent characters and terminating
NULs. This fixes resource lookup; PNVM matching, transfer, completion, subsequent
initialization and wireless networking still need hardware validation.

## Build

Use the **BE200 Tahoe build** workflow with the Debug or Release configuration.
It builds the source in this repository, using MacKernelSDK commit
`3f750085caa17ec3a7880f11c11bf4f48cd6a164`. Jobs have a 20-minute timeout.
Source changes on the development branch also trigger one Debug build.
Artifacts and compiler logs are retained for 7 days. Builds are not physical
validation and are not automatically published as releases.

The pinned SDK predates the public MSI-X declaration. The preparation script
checks its exact header hash, then replaces the reserved virtual slot with
Apple's `IOPCIDevice::configureInterrupts` declaration. This dependency patch
is for the Tahoe target. It does not modify a system framework or kernel.
See [Apple's header](https://github.com/apple-oss-distributions/IOPCIFamily/blob/main/IOKit/pci/IOPCIDevice.h)
for the slot and API signature.

The local commands are:

```sh
python3 scripts/prepare_tahoe_sdk.py
xcodebuild -project itlwm.xcodeproj -scheme AirportItlwm-Tahoe \
  -configuration Debug ARCHS=x86_64 CODE_SIGNING_ALLOWED=NO build
```

## Sources

- [laobamac/itlwm](https://github.com/laobamac/itlwm) supplies the native Tahoe
  Apple wireless interface and the source baseline.
- [OpenIntelWireless issue 955](https://github.com/OpenIntelWireless/itlwm/issues/955)
  contains zxystd's experimental BE200 binaries. The linked binaries do not
  contain corresponding C/C++ source and are not build inputs here.
- [Linux iwlwifi GL/BZ configuration](https://github.com/torvalds/linux/blob/v6.12/drivers/net/wireless/intel/iwlwifi/cfg/bz.c)
  distinguishes discrete GL from integrated BZ transport.
- [OpenBSD iwx source](https://github.com/openbsd/src/blob/master/sys/dev/pci/if_iwx.c)
  provides reference BZ transport and MLD firmware-command implementations.
  Its device table is not a ready-made match for this BE200 adapter.

All inherited source attribution, GPLv2 terms and Intel firmware licensing
remain applicable. Original upstream source headers are preserved.

## Firmware inputs

The initial GL firmware and PNVM were recovered without alteration from the
zlib-compressed arrays in zxystd's [original Ventura test package](https://github.com/OpenIntelWireless/itlwm/files/15457871/Ventura.zip).
The package executable SHA-256 is
`b4555bd8d7062ba625dd5f186d138508f5adac6cde5051180bcc1475b8f810b7`.
These are Intel firmware binaries, distributed under [Intel's firmware license](iwlwifi-firmware-license).

used to select wire structures; newer OpenBSD firmware structures are not
assumed to match this older firmware.
